# 찐청소 가독성 기준

## 변경 금지
- 읽기 편하게 만든다는 이유로 문구·조건·제외 항목·FAQ 답변을 삭제하거나 요약하지 않는다.
- 본문을 line-clamp, 고정 높이, overflow hidden으로 잘라내거나 새 아코디언으로 숨기지 않는다.
- 실제 사례와 사진 설명, SEO 제목·메타·구조화 데이터·링크는 디자인 변경과 분리한다.
- PC와 모바일을 함께 검증한다. 배포는 사용자 확인 전 금지한다.

## 화면 기준
- 본문 16~18px, 보조 설명 14px 이상을 기본으로 한다. 작은 숫자·장식 라벨은 별도 판단한다.
- 긴 한글 문장은 단어 단위로 줄바꿈하되 긴 URL 등은 화면을 넘기지 않게 한다.
- 모바일에는 억지로 여러 열을 유지하지 않는다. PC 본문 최대 폭 48rem.
- 목차 링크는 최소 44px 높이. 고정 헤더 아래로 제목이 드러나는지 실제 이동으로 확인한다.
- 목차 메뉴는 박스 없이 텍스트와 장식용 왼쪽 화살표 3개로 표시한다. 모션 감소 설정에서는 움직임을 끈다.
- 목차 내부 스크롤은 사용하지 않는다. PC 높이 1000px 이상에서만 고정하고, 낮은 화면에서는 페이지와 함께 스크롤한다. 새 메뉴를 추가하면 고정 상태에서 마지막 항목까지 화면에 들어오는지 다시 검증한다.
- 이미지 전후 표시·순서·alt를 유지한다. 표는 데이터를 보존하며 재배치한다.
- 최소 320/390/768/1280px에서 가로 넘침, 고정 요소 충돌, 문구 잘림을 확인한다.
- 본문·링크·이미지·SEO의 변경 전후 비교, 프로덕션 빌드, 브라우저 새로고침까지 확인한다.

## 모바일 문장 배치 (공통)
- `ReadingParagraph`는 원문 문자와 공백을 그대로 유지하며 문장 경계에 span만 추가한다.
- 639px 이하에서 문장별로 줄을 바꾸고 문장 사이에 0.75em 여백을 둔다. PC에서는 inline으로 이어진다.
- 긴 문장은 검토한 의미 단위만 `breakAfter`로 지정한다. 글자 수 기준으로 자동 절단하거나 표현을 고쳐 쓰지 않는다.
- "한 문장 한 줄"은 한 화면 줄에 억지로 넣는 뜻이 아니다. 화면 너비에 따른 자연스러운 줄바꿈을 허용한다.
- 숫자·조건·예외·FAQ를 보존하고, 검색용 별도 본문이나 모바일 전용 축약문은 만들지 않는다.

## 검증
지역페이지는 지역명만 치환한 설명을 늘리지 않는다. 안양 예시는 등록된 지역 사진과 공간 유형에 맞는 상담 조건을 연결한다. 일반적인 상담 안내와 실제 현장의 작업 기록을 명확히 구분하며, 인원·시간·금액·작업 방법의 선택 이유는 확인된 기록이 있을 때만 사례로 기재한다. 상세 기록이 부족하면 별도 사례 URL을 생성하지 않는다.
- `node work/service-readability-audit.cjs`: 35개 페이지의 기존 본문·링크·사진·제목·메타·JSON-LD 보존 및 목차 복귀 구조 확인. 3101 로컬 서버가 필요하다.
- 원본 기준 파일을 변경 후 결과로 덮어쓰지 않는다. 새 서비스는 검증 대상 목록에 추가하고, 기존 페이지의 기준은 유지한다.
- `node --test tests/*.test.mjs`와 `npm run build`를 실행한다.
- 화면 폭별 가로 넘침 검사와 별도로 실제 스크린샷, 메뉴 이동, 복귀 및 헤더 가림을 확인한다.
